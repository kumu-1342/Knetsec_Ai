## 1. 引言

### 1.1 编写目的

本文把「做一个 AI 安全 × 网络安全实时情报平台」这一句话，拆解为**可开发、可测试、可验收**的需求条目，作为以下工作的唯一依据：

1. 开发：后端、采集器、管理面板的实现范围与接口边界；
2. 测试：验收标准（每条第 2、3 小点）即测试用例的来源；
3. 验收：Lead 在 M4 阶段逐条勾选，形成《07-测试与验收报告》；
4. 变更管理：任何新需求先进入本文，再进入《00-项目总览与架构契约》与 `packages/shared` 类型，避免「口头需求」直接改代码。

### 1.2 需求范围

本文覆盖 Knetsec_Ai v1.0（单机部署、单租户）的全部需求：

- 多源情报采集（GitHub / 漏洞库 / 厂商 / 研究机构 / 安全媒体 5 类，≥ 12 个可用源）；
- 归一化、去重、富化（CVSS 分级、KEV 标记、AI 安全标签、importance 排序）；
- 定时与手动采集任务、运行记录与失败可见；
- 日报/周报/月报/自定义报告的自动生成、预览与下载；
- 中文管理面板（登录、仪表盘、情报中心、数据源、任务、报告、设置、审计）；
- 安全与运维要求（JWT、scrypt、限流、审计、备份、部署脚本）。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 情报条目（Item） | 一条去重后的情报事实，对应 `items` 表一行 |
| 数据源（Source） | 一个可采集的外部入口，对应 `sources` 表一行，绑定一个适配器 |
| 适配器（Adapter） | 把某类上游数据转换为 `RawItem[]` 的代码，共 10 种 |
| 采集运行（Fetch Run） | 一次「按源采集 → 去重 → 富化 → 入库」的执行记录 |
| 去重键（uid） | `sha256(sourceKey + ':' + externalId)`，无外部 ID 时回退为规范化标题哈希 |
| 富化（Enrich） | 依据 CVSS / KEV / 关键词计算 severity、tags、importance |
| KEV | CISA Known Exploited Vulnerabilities，已知被在野利用漏洞清单 |
| GHSA | GitHub Security Advisory，GitHub 安全公告编号 |
| admin / viewer | 管理员（可写）/ 只读用户（仅查询） |
| P0 / P1 / P2 | 需求优先级：必须交付 / 应当交付 / 可延后 |

## 2. 产品概述

### 2.1 产品定位

**Knetsec_Ai —— AI 安全 × 网络安全实时情报平台**：从公开渠道实时采集 AI 安全与网络安全情报，自动完成归一化、去重、分级、打标，一键生成结构化报告，并通过中文管理面板完成数据源管理、任务调度、报告分发与运营。

产品由三部分组成：**采集器（10 类适配器）× 流水线（归一化/去重/富化）× 管理面板（Vue3）**，底座是单文件 SQLite，整个系统一条命令启动。

### 2.2 业务背景与待解决问题

运营方在做「AI × 网络安全」知识星球，固定栏目「AI 安全情报周报」每周产出。当前人工方式存在四个结构性痛点，本产品的需求即围绕这四点展开：

| 痛点 | 现状 | 本产品的对策 | 对应需求 |
|---|---|---|---|
| 入口分散 | 每天几十个入口人工巡检，单次 40-60 分钟 | 内置 ≥ 12 个源、5 类来源，定时自动采集 | FR-32、FR-20 |
| 重复严重 | 同一 CVE 被 3-8 个渠道重复报道 | uid 去重 + 批内去重 + 跨源标题相似度去重 | FR-33 |
| 时效滞后 | 0day / KEV 窗口只有数小时 | 采集间隔可配（默认 360 分钟，KEV 源可调至 60 分钟）、手动一键采集 | FR-20、FR-19 |
| 无法沉淀 | 链接散落在收藏夹，不可检索、不可统计 | 结构化条目 + 多维筛选 + 报告落盘 + 统计趋势 | FR-07、FR-23、FR-06 |

### 2.3 产品目标与成功度量

需求来源于目标，目标的可度量口径如下（与《00》§1.2 的 G1-G6 一致）：

| 目标 | 度量指标 | 达标阈值 |
|---|---|---|
| G1 多源实时采集 | 可用的内置源数量；单源失败是否影响整轮 | ≥ 12 个；单源失败不影响其他源（partial） |
| G2 自动去重与打标 | 同 uid 重复率；自动打标覆盖率 | 重复入库 0 条；分类/严重度非 unknown 覆盖率 ≥ 90% |
| G3 自动报告 | 一键生成周报耗时；产物可读性 | ≤ 10 秒；Markdown + 单文件 HTML 可直接复制/打印 |
| G4 管理面板 | 契约 §10 的 8 个路由是否全部可用 | 8/8 可用，中文界面 |
| G5 可运维 | 从零启动命令数；备份/恢复可行 | 1 条命令启动；SQLite 单文件可整库备份 |
| G6 工程质量 | 类型检查、测试、文档 | strict 0 error；核心纯函数有单测；文档 00-09 齐全 |

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 系统标识 | 典型用户 | 职责 | 权限概要 |
|---|---|---|---|---|
| 运营管理员 | `admin` | 知识星球主理人、安全运营 | 日常巡检、来源维护、触发采集、生成与发布报告、改系统设置 | 全部读写 |
| 只读用户 | `viewer` | 实习生、合作作者、审稿人 | 查阅情报、预览/下载报告，不改任何数据 | 仅查询类接口 |
| 系统（调度器） | 内部身份 | — | 定时采集、定时生成周报、每日清理 | 不经 API，直接调用服务层 |

> v1.0 只有这两个角色。多租户、团队协作、细粒度数据权限（按分类授权）均为**非目标**（见 §7）。

### 3.2 权限矩阵

「✓」允许，「✗」禁止（返回 403 FORBIDDEN），「—」不涉及。

| 能力 | admin | viewer | 说明 |
|---|---|---|---|
| 登录 / 查看当前用户 / 修改自己的密码 | ✓ | ✓ | 修改密码需校验旧密码 |
| 仪表盘聚合数据 | ✓ | ✓ | 只读 |
| 情报列表 / 详情 / 导出 | ✓ | ✓ | 导出属于读操作 |
| 标记已读 / 星标 / 批量操作 | ✓ | ✗ | 写库操作，写审计 |
| 数据源列表 | ✓ | ✓ | 只读 |
| 数据源试采 | ✓ | ✗ | 会发起真实外部请求并写审计，按写操作处理 |
| 数据源新增 / 修改 / 启停 / 删除 | ✓ | ✗ | 写库操作，写审计 |
| 手动触发采集 | ✓ | ✗ | 写库操作，写审计 |
| 运行记录 / 运行详情 / 调度状态 | ✓ | ✓ | 只读 |
| 报告列表 / 详情 / 预览 / 下载 | ✓ | ✓ | 只读 |
| 生成报告 / 删除报告 | ✓ | ✗ | 写库操作，写审计 |
| 读取系统设置 | ✓ | ✓ | LLM Key 脱敏后返回 |
| 更新系统设置 | ✓ | ✗ | 写库操作，写审计 |
| 审计日志查询 | ✓ | ✗ | 含操作者 IP 等敏感信息 |
| 系统信息 / 健康检查 | ✓ | ✓ | 健康检查公开 |

### 3.3 用户画像与典型一天

**画像 A：运营（admin）**——每周一 08:30 打开面板：先看仪表盘 14 天趋势与严重度分布，确认上周新增量；进「情报中心」按「重点关注 + 严重度 ≥ 高危 + 近 7 天」筛选，逐条判断、星标值得写的；点「一键生成周报」，打开报告预览，复制 Markdown 到编辑器补点评；如发现某源 last_status 连续 failed，去「数据源」页看 last_error 并试采排查。

**画像 B：只读（viewer）**——每天下午打开面板查「AI 安全」分类有无新条目，点开详情抽屉看摘要与原文链接，下载最新周报 HTML 打印；不能改状态、不能触发生成。

## 4. 功能性需求

### 4.1 编号规则与优先级

- 编号：`FR-<两位序号>`，一经分配不复用；废弃需求保留编号并标注「已废弃」。
- 优先级：**P0** = 首个可交付版本必须完成，缺失则验收不通过；**P1** = 应当完成，可在联调期补齐；**P2** = 可延后到 v1.1。
- 每条需求固定包含：**描述**（做什么、为什么）、**优先级**、**验收标准**（可观察、可复现）、**关联接口/页面**。

### 4.2 认证与账号

#### FR-01 用户登录

**描述**：用户以用户名 + 密码登录，服务端校验 scrypt 哈希后签发 JWT（默认 12 小时），返回 token、有效期与用户信息（含角色、是否需改密）。登录失败必须给出统一提示，不区分「用户不存在 / 密码错误」，防止账号枚举；同一 IP 每分钟最多 5 次登录尝试（超过返回 429 RATE_LIMITED）。登录成功写审计日志（`auth.login`）；失败只写应用日志（warn）并计入限流，不写审计。
**优先级**：P0
**验收标准**：
1. 正确凭据返回 `success:true`，`data.token` 非空且可访问受保护接口；
2. 错误凭据返回 401，`error.code=UNAUTHORIZED`，message 不暴露用户是否存在；
3. 同 IP 1 分钟内第 6 次请求返回 429，`error.code=RATE_LIMITED`；
4. `audit_logs` 可查到本次 `login` / `login_failed` 记录（含 IP）。
**关联**：接口 `POST /api/v1/auth/login`；页面 `/login`。

#### FR-02 查看当前用户

**描述**：返回当前登录用户的基本信息与角色，供面板初始化用户态、决定菜单可见性（viewer 隐藏写操作按钮）。
**优先级**：P0
**验收标准**：
1. 携带有效 token 返回 `id/username/displayName/role/mustChangePassword/lastLoginAt`；
2. 无 token 或 token 过期返回 401。
**关联**：`GET /api/v1/auth/me`；全局路由守卫。

#### FR-03 修改密码

**描述**：登录用户凭旧密码修改新密码；新密码长度 ≥ 8 且同时包含字母与数字；修改成功后清除 `must_change_password` 标记并写审计。默认管理员首次启动时 `mustChangePassword=true`，面板在每次登录后以不可忽略的方式提示先改初始密码。
**优先级**：P0
**验收标准**：
1. 旧密码错误返回 400/401，密码不变；
2. 新密码为 7 位或纯数字返回 400 `VALIDATION_ERROR`，提示具体原因；
3. 修改成功后旧 token 仍可用（受 12h 有效期约束），新密码可重新登录；
4. 审计日志出现 `change_password` 记录，detail 中不含明文密码。
**关联**：`POST /api/v1/auth/change-password`；登录后弹窗。

#### FR-04 角色权限控制

**描述**：所有写操作（改条目状态、批量操作、源增删改/启停、触发采集、生成/删除报告、更新设置、查审计）仅 admin 可执行；viewer 调用返回 403 且不产生副作用。
**优先级**：P0
**验收标准**：
1. viewer 调用任写接口返回 403 `FORBIDDEN`，数据库无变化；
2. 未登录调用任一受保护接口返回 401；
3. 面板对 viewer 隐藏写操作入口（按钮/表单），直接构造请求仍被服务端拒绝（前端隐藏不是安全边界）。
**关联**：全局鉴权钩子 + 路由级角色守卫；所有页面。

#### FR-05 默认管理员与初始数据

**描述**：首次启动自动建库、执行迁移，并在没有任何 admin 用户时创建默认管理员（用户名/密码可用环境变量 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 覆盖，默认 `admin/admin123`；标记 `mustChangePassword=true`）、写入默认数据源与默认系统设置。重复启动必须幂等，不得重复插入。
**优先级**：P0
**验收标准**：
1. 空目录首次启动后可用默认账号登录；
2. 第二次启动不重复创建用户/源（数量不变）；
3. 默认数据源数量与《04-数据源接入与采集设计》清单一致。

### 4.3 仪表盘

#### FR-06 仪表盘聚合数据

**描述**：一次请求返回首页所需的全部聚合数据：总量/今日/近 7 天/未读/近 7 天严重事件、数据源与报告数量；严重度分布、分类分布、来源分布；最近 14 天按天趋势（总量、AI 安全、漏洞）；最新情报（前 5-10 条）与最近采集任务（前 5 条）。聚合查询需走索引，避免全表扫描。
**优先级**：P0
**验收标准**：
1. 返回结构符合 `DashboardSummary`（shared 类型），字段完整；
2. 手工插入 3 条不同严重度条目后，分布与总数一致；
3. 空库时返回全 0 与空数组，不报错；
4. 响应时间在 1 万条数据量下 ≤ 500 ms。
**关联**：`GET /api/v1/dashboard/summary`；页面 `/dashboard`。

### 4.4 情报中心

#### FR-07 情报分页查询

**描述**：支持组合筛选：关键词（标题/摘要模糊匹配）、分类、严重度、来源 key、发布时间区间、已读/未读、星标、重点关注（命中 watchKeywords）、排序字段（published_at/fetched_at/severity/importance）与方向（asc/desc）、分页（page 从 1 起，pageSize ≤ 100，默认 20）。关键词需转义 LIKE 通配符；SQL 全参数化。
**优先级**：P0
**验收标准**：
1. 单条件与多条件组合筛选结果正确，total 与 totalPages 自洽；
2. `pageSize=200` 时被夹到 100 或返回 400（不返回超量数据）；
3. 关键词含 `%`、`_`、`'` 时行为正确且无 SQL 注入；
4. 排序对空值（published_at 为 NULL）有确定行为，不抛错。
**关联**：`GET /api/v1/items`；页面 `/items`。

#### FR-08 情报详情

**描述**：按 id 返回单条情报全部展示字段（不含 raw 原始快照，raw 仅排障用）；不存在返回 404。
**优先级**：P0
**验收标准**：
1. 返回 `ItemDTO` 全字段，tags/cveIds/ghsaIds 为数组；
2. 不存在 id 返回 404 `NOT_FOUND`；
3. 详情抽屉可展示原文链接（新窗口打开，rel=noopener）。
**关联**：`GET /api/v1/items/:id`；详情抽屉。

#### FR-09 标记已读 / 星标

**描述**：admin 可单条更新 `isRead`/`isStarred`，用于运营进度管理。单条更新不写审计（批量操作才写审计）。
**优先级**：P1
**验收标准**：
1. 更新后列表与详情状态一致；
2. 传非法字段返回 400；空 body 返回 400；
3. viewer 调用 403。
**关联**：`PATCH /api/v1/items/:id`；行内星标、详情抽屉。

#### FR-10 批量操作

**描述**：admin 对选中条目批量「标记已读 / 标记未读 / 星标 / 取消星标 / 删除」；ids 数量上限 500，超限 400；删除为物理删除并写审计（detail 记录条数，不逐条记录避免日志膨胀）。
**优先级**：P1
**验收标准**：
1. 批量操作影响行数与请求 ids 有效数量一致；
2. 含不存在 id 时不报错，返回实际影响条数；
3. 空数组或 > 500 返回 400；
4. viewer 调用 403。
**关联**：`POST /api/v1/items/bulk`；列表多选工具栏。

#### FR-11 导出情报

**描述**：按与列表相同的筛选条件导出 CSV / JSON / Markdown 三种格式；导出上限 5000 条并在超出时截断（响应头或首行注明）；CSV 需正确转义逗号、引号、换行，并加 UTF-8 BOM 以便 Excel 打开不乱码。
**优先级**：P1
**验收标准**：
1. 三种格式均可下载，文件名含日期；
2. CSV 用 Excel 打开中文不乱码、列不串行；
3. 筛选条件与列表一致，导出条数 ≤ 5000；
4. viewer 可导出。
**关联**：`GET /api/v1/items/export`；列表「导出」按钮。

#### FR-12 重点关注识别

**描述**：条目若命中系统设置中的 `watchKeywords`（标题/摘要，大小写不敏感），列表接口在 `watched=true` 时返回这些条目；面板在列表中给出视觉标记。
**优先级**：P1
**验收标准**：
1. 设置关键词后，`watched=true` 只返回命中条目；
2. 关键词为空时 `watched=true` 返回空列表（而非全部）；
3. 修改设置后无需重启即生效。
**关联**：`GET /api/v1/items?watched=true`；列表筛选器。

### 4.5 数据源管理

#### FR-13 数据源列表

**描述**：返回全部数据源（含停用），字段含状态、采集间隔、优先级、最近运行时间/状态/错误、累计成功/失败次数；按 `priority` 升序、`id` 升序返回。配置中的密钥类字段不得出现在响应中（如 GitHub Token 属于环境变量，不入库；若未来入库需脱敏）。
**优先级**：P0
**验收标准**：
1. 返回 `SourceDTO[]`，config 为对象而非字符串；
2. lastError 仅在失败时有值；
3. viewer 可查看但看不到写按钮。
**关联**：`GET /api/v1/sources`；页面 `/sources`。

#### FR-14 新增数据源

**描述**：admin 新建数据源，必填 key（稳定唯一，小写字母/数字/连字符）、名称、分类、适配器；可选 url、config、enabled、intervalMinutes、priority。服务端校验 key 唯一（重复 409）、adapter 属于 10 种枚举、config 必须为对象；适配器在采集/试采时自行校验并补默认值（缺字段不崩溃）。
**优先级**：P0
**验收标准**：
1. 合法请求返回新源对象；
2. 重复 key 返回 409 `CONFLICT`；
3. 非法 adapter / 非法 category 返回 400；
4. 新建后立即出现在列表并参与调度（enabled=1 时）。
**关联**：`POST /api/v1/sources`；「新增数据源」表单。

#### FR-15 修改数据源

**描述**：admin 修改名称、url、config、intervalMinutes、priority、enabled；`key` 与 `adapter` 创建后不可改（改 adapter 等于换语义，应新建源），尝试修改返回 400。
**优先级**：P1
**验收标准**：
1. 修改后列表与调度立即生效；
2. 尝试改 key/adapter 返回 400 且数据不变；
3. viewer 调用 403。
**关联**：`PATCH /api/v1/sources/:id`；编辑抽屉。

#### FR-16 数据源启停

**描述**：admin 一键启用/停用数据源；停用后调度器跳过该源，但保留历史条目与统计。
**优先级**：P0
**验收标准**：
1. 停用后下一次调度不含该源（调度状态可验证）；
2. 重新启用后恢复调度；
3. 开关状态持久化，重启后保持。
**关联**：`POST /api/v1/sources/:id/toggle`；列表开关。

#### FR-17 数据源试采

**描述**：admin 对单个源执行一次采集但不入库，返回 ok、适配器、抓取条数、耗时与前 5 条样本标题/错误，用于排障与新建源时的配置验证。必须受超时保护（≤ 60 秒）且不干扰正在运行的采集。
**优先级**：P0
**验收标准**：
1. 可达源返回 `ok=true, fetched>0, sample.length<=5`；
2. 不可达源返回 `ok=false, error` 非空且 HTTP 状态码不视为服务端错误（200 信封内 ok=false）；
3. 试采不新增 items 记录；
4. viewer 调用 403。
**关联**：`POST /api/v1/sources/:id/test`；列表「试采」按钮。

#### FR-18 删除数据源

**描述**：admin 删除数据源登记；**已采集的历史条目保留**（source_key 冗余在 items 上，源改名/删除不影响历史展示）。
**优先级**：P1
**验收标准**：
1. 删除后源从列表消失；
2. 该源历史条目仍可在情报中心查到，sourceName 仍显示；
3. 不存在 id 返回 404；
4. 审计记录删除动作。
**关联**：`DELETE /api/v1/sources/:id`；列表删除确认框。

### 4.6 采集任务

#### FR-19 手动触发采集

**描述**：admin 触发一轮采集，可指定 sourceKeys 子集（为空/缺省 = 全部启用源）；接口立即返回 202 + runId，采集在后台异步执行；同一时刻只允许一个采集运行，重复触发返回 409 CONFLICT（或在运行记录中给出提示）。触发写审计。
**优先级**：P0
**验收标准**：
1. 触发后立即得到 `{ runId, status }`，HTTP 202；
2. 运行期间再次触发返回 409，不产生第二个并发运行；
3. 运行结束后 `fetch_runs` 状态为 success/partial/failed，计数与实际入库一致；
4. 指定不存在的 sourceKey 返回 400。
**关联**：`POST /api/v1/tasks/fetch`；页面 `/tasks`。

#### FR-20 定时调度

**描述**：内置调度器每 5 分钟扫描启用源，满足 `last_run_at + interval_minutes <= now` 的源入队采集（限并发，默认 2）；另有报告定时任务（默认周一 08:00 生成周报）与每日清理任务（按 retentionDays 清理过期条目与旧运行日志）。调度器可用 `KNETSEC_SCHEDULER=off` 关闭（只允许手动）。所有定时任务失败不得导致进程退出。
**优先级**：P0
**验收标准**：
1. 启动日志可见调度器已启动及各任务下次执行时间；
2. 将某源 intervalMinutes 设为 1 并等待，可见自动采集运行记录；
3. 定时任务抛错时进程存活且错误写日志；
4. 关闭调度器后无自动运行记录。
**关联**：调度器服务；`/tasks/status`。

#### FR-21 运行记录与详情

**描述**：分页查询采集运行历史（触发方式/状态/起止时间/源总数/成功/失败/新增/重复/错误），并按 id 查看详情（逐行日志，单条日志 ≤ 1000 行，超出截断并提示）。
**优先级**：P0
**验收标准**：
1. 列表按 startedAt 倒序，分页正确；
2. 详情返回 logs 数组，可按行渲染；
3. 运行中记录 status=running 且有开始时间、无结束时间；
4. viewer 可查看。
**关联**：`GET /api/v1/tasks/runs`、`GET /api/v1/tasks/runs/:id`；页面 `/tasks`。

#### FR-22 调度器状态

**描述**：返回调度器是否启用、当前是否有运行、下次到期源列表（key/名称/计划时间）、各定时任务下次执行时间，供运维判断「为什么没采」。
**优先级**：P1
**验收标准**：
1. 返回结构稳定，空库时列表为空数组；
2. 手动运行中时 `running=true`；
3. 停用调度器后 `schedulerEnabled=false`。
**关联**：`GET /api/v1/tasks/status`；页面 `/tasks` 顶部状态卡。

### 4.7 报告中心

#### FR-23 生成报告

**描述**：admin 一键生成报告：可指定类型（daily/weekly/monthly/custom）、区间（缺省按类型推断：日报=昨天、周报=最近 7 天、月报=最近 30 天）、标题与 itemIds（专题报告）。生成过程聚合区间条目 → 按 7-9 个章节渲染 Markdown → 生成内联 CSS 的独立 HTML → 写 `reports` 表并落盘 `data/reports/<id>-<type>-<yyyyMMdd>/`。成功后写审计。
**优先级**：P0
**验收标准**：
1. 生成接口返回报告 id 与摘要，列表立即可见；
2. 落盘目录含 report.md 与 report.html，HTML 双击可在浏览器打开、无外部依赖；
3. 报告章节顺序与 settings.reportSections 一致，缺数据的章节不输出空标题；
4. itemIds 专题报告只包含指定条目；
5. viewer 调用 403。
**关联**：`POST /api/v1/reports/generate`；页面 `/reports`。

#### FR-24 报告列表 / 详情 / 预览

**描述**：分页查询报告（类型筛选，倒序），详情返回 Markdown 与 HTML 全文；列表行展示标题、类型、区间、条目数、生成时间、生成人与前 800 字预览。Markdown 渲染必须经 DOMPurify 消毒，防 XSS。
**优先级**：P0
**验收标准**：
1. 列表分页与筛选正确；
2. 详情 `ReportDetailDTO` 含 markdown/html；
3. 预览页（`/reports/:id`）可渲染 Markdown、可打印；
4. 恶意 HTML/Markdown（`<script>`）在预览中被消毒。
**关联**：`GET /api/v1/reports`、`GET /api/v1/reports/:id`；页面 `/reports`、`/reports/:id`。

#### FR-25 报告下载

**描述**：按 `format=md|html` 下载报告文件，`Content-Disposition` 文件名为 `knetsec-report-<id>-<type>-<yyyyMMdd>.md/.html`；内容从数据库即时生成，不依赖落盘文件（文件被误删仍可下载）。
**优先级**：P0
**验收标准**：
1. 两种格式均可下载且内容与详情一致；
2. 中文文件名在 Windows 浏览器下载不乱码；
3. 删掉落盘文件后仍能下载（重建）；
4. viewer 可下载。
**关联**：`GET /api/v1/reports/:id/download`；报告列表「下载」。

#### FR-26 删除报告

**描述**：admin 删除报告记录与落盘文件；删除写审计。
**优先级**：P1
**验收标准**：
1. 删除后列表不可见、文件目录被清理；
2. 不存在 id 返回 404；
3. viewer 调用 403。
**关联**：`DELETE /api/v1/reports/:id`；列表删除。

### 4.8 设置、审计与系统

#### FR-27 读取系统设置

**描述**：返回全部系统设置（关键词、报告章节与回看天数、通知、LLM、保留天数、默认采集间隔）；`llmApiKey` 必须脱敏返回（如 `sk-****abcd`），绝不明文返回。
**优先级**：P0
**验收标准**：
1. 返回 `SettingsDTO` 全字段；
2. 配置 Key 后读取，响应中不含明文 Key；
3. viewer 可读取（面板展示为只读）。
**关联**：`GET /api/v1/settings`；页面 `/settings`。

#### FR-28 更新系统设置

**描述**：admin 更新设置，支持部分更新；`llmApiKey` 传空字符串表示保持原值；保存后立即生效（关键词/章节/间隔影响后续采集与报告，无需重启）；写审计（detail 中不得包含 Key 明文）。
**优先级**：P0
**验收标准**：
1. 部分更新不影响未提交字段；
2. 修改 watchKeywords 后立即影响 `watched` 筛选与报告导语；
3. 空 Key 提交后原 Key 仍有效（脱敏值不变）；
4. viewer 调用 403；审计无明文密钥。
**关联**：`PUT /api/v1/settings`；设置页各 Tab。

#### FR-29 审计日志

**描述**：分页查询审计日志（登录、改密、源增删改/启停、触发采集、生成/删除报告、批量操作、改设置），字段含操作者、动作、对象、详情 JSON、IP、时间；支持按用户（精确匹配）与动作（模糊匹配）筛选；仅 admin 可见。
**优先级**：P1
**验收标准**：
1. 上述每个写操作都产生一条审计记录；
2. 分页与筛选正确；
3. viewer 调用 403；
4. 日志只增不改不删（v1.0 不提供删审计接口）。
**关联**：`GET /api/v1/audit-logs`；页面 `/audit`。

#### FR-30 系统信息与健康检查

**描述**：系统信息返回版本、运行环境、启动时间/运行时长、数据库文件大小、条目与源数量、调度器状态；健康检查公开，返回进程与数据库连通性（`SELECT 1`），供运维脚本/容器 HEALTHCHECK 使用。健康检查不得泄露任何敏感配置。
**优先级**：P0
**验收标准**：
1. 健康检查在数据库可用时返回 200 且 `status=ok`；
2. 数据库不可用时返回 5xx（当前实现为 500 `INTERNAL_ERROR`），探活以 HTTP 200 判定健康；
3. 系统信息需登录，含版本与库大小；
4. 健康检查不含任何敏感信息；系统信息返回 `dataDir`/`dbPath` 绝对路径（仅登录用户可见，属运维信息）。
**关联**：`GET /api/v1/system/info`、`GET /api/v1/health`；页脚版本号、部署脚本健康探测。

#### FR-31 在线 API 文档

**描述**：提供 Swagger UI（`/docs`）与 OpenAPI JSON（`/openapi.json`），覆盖全部路由、鉴权方式、请求/响应结构，供前端联调与第三方集成；两者均公开可访问（内容不含敏感信息）。
**优先级**：P1
**验收标准**：
1. 浏览器打开 `/docs` 可加载并展开各端点；
2. `/openapi.json` 为合法 OpenAPI 3 文档，路径与《09-API接口文档》一致；
3. 在 Swagger 中填 token 后可成功调用受保护接口。
**关联**：`GET /docs`、`GET /openapi.json`。

### 4.9 采集与流水线

#### FR-32 多源采集适配器

**描述**：实现 10 种适配器（github_advisories、github_search、github_releases、nvd_cve、cisa_kev、msrc_cvrf、arxiv、rss、json_list、html_list），内置 ≥ 12 个可用数据源、覆盖 5 类来源；适配器只做「外部数据 → RawItem[]」，不写库、不去重；单条解析失败跳过并记 warnings，整体失败才抛错；统一 HTTP 客户端提供超时（默认 20s）、重试（429/5xx 指数退避）、UA、代理、响应体上限。
**优先级**：P0
**验收标准**：
1. 10 种适配器均可通过试采在可达源上返回 `RawItem[]`；
2. 同源连续两次采集，externalId 稳定（幂等）；
3. 单源抛错时运行状态为 partial，其他源正常入库；
4. warnings 出现在运行日志中；
5. 配置缺失字段时使用默认值，不崩溃。
**关联**：`apps/server/src/collectors/**`；`POST /api/v1/sources/:id/test`；《04》。

#### FR-33 归一化与去重

**描述**：RawItem 经归一化（补 publishedAt、分类、语言、uid、CVE/GHSA 提取）后进入去重：批内按 uid 去重；库内 `INSERT ... ON CONFLICT(uid) DO NOTHING`；跨源标题 3-gram Jaccard ≥ 0.85 且同分类且时间差 ≤ 3 天判为重复（保留 priority 数值更小的源）；CVE/GHSA 相同视为重复。去重结果计入 `items_new`/`items_duplicate`。
**优先级**：P0
**验收标准**：
1. 同 uid 两次入库只保留 1 条；
2. 批内重复被合并且计数正确；
3. 高度相似标题的跨源条目被识别为重复（以单测样例验证）；
4. 不同事件不会因标题短而误判（相似度阈值可调，默认 0.85）。

#### FR-34 富化（分级 / 打标 / 排序）

**描述**：依据 CVSS 阈值（≥9 critical、≥7 high、≥4 medium、>0 low）推导 severity；KEV 强制 ≥ high；命中 AI 安全词典打 tags 并可将分类提升为 ai-security；计算 importance(0-100)：严重度 40 + KEV 20 + 关注关键词 15 + 24h 内 10 + 有 CVE 10 + 有 PoC 5（上限 100）。可选 LLM 摘要默认关闭，超时 20s 跳过且不阻塞流水线。
**优先级**：P0
**验收标准**：
1. 给定 CVSS 9.8 的条目 severity=critical、importance 显著高于 medium；
2. isKev=true 的条目 severity 至少 high；
3. 标题含 prompt injection 的条目 tags 含 `prompt-injection`，分类为 ai-security；
4. LLM 关闭时无外部请求；开启后超时不阻塞入库。

#### FR-35 严重事件通知

**描述**：开启通知后，若本轮新增包含 critical 或 KEV 条目，按 `notificationChannel`（generic/wecom/dingtalk/feishu）向 `notificationWebhook` POST JSON；通知失败只记日志与运行 warnings，不影响采集结果；Webhook 为空时跳过并提示。
**优先级**：P2
**验收标准**：
1. 关闭通知时无任何外发请求；
2. 开启且存在 critical 新增时，目标 Webhook 收到一次含条目标题的报文；
3. Webhook 不可达时采集仍成功，warnings 含通知失败原因。
**关联**：设置页「通知」；运行日志。

#### FR-36 数据保留与清理

**描述**：每日维护任务按 `retentionDays`（默认 180）清理过期情报（以 publishedAt/fetchedAt 中较新者判断），并清理超过 30 天的历史运行日志，避免库无限膨胀；清理条数写日志。不清理报告、审计日志、数据源。
**优先级**：P2
**验收标准**：
1. 构造过期条目后，维护任务执行后被删除；
2. 未过期条目保留；
3. 清理动作可在运行日志/应用日志中查到条数；
4. 保留天数可在设置页修改。

#### FR-37 失败可见与容错

**描述**：采集失败必须在面板可见：源的 `last_status`/`last_error` 更新、运行记录 status=partial/failed 且 logs 含原因；上游结构变更导致解析失败不崩溃进程；连续失败的源不自动禁用（避免静默停采），但面板标红。
**优先级**：P1
**验收标准**：
1. 故意配置错误 URL 的源失败后，列表显示 lastStatus=failed 与错误摘要；
2. 失败不影响同轮其他源；
3. 进程在失败后继续服务（健康检查 200）；
4. 面板对 failed 源有视觉区分。

## 5. 非功能性需求

### 5.1 性能（NFR-P）

| 编号 | 指标 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-P1 | 列表接口 P95 响应（1 万条数据量） | ≤ 300 ms | 压测/日志耗时 |
| NFR-P2 | 仪表盘接口 P95 | ≤ 500 ms | 同上 |
| NFR-P3 | 单源试采响应 | ≤ 30 s（超时中断） | 试采计时 |
| NFR-P4 | 全量一轮采集（12 源） | ≤ 5 min（含限流等待） | 运行记录耗时 |
| NFR-P5 | 周报生成 | ≤ 10 s | 生成接口耗时 |
| NFR-P6 | 首屏加载（本地） | ≤ 3 s | 浏览器 Performance |
| NFR-P7 | 数据库容量 | 10 万条条目、库文件 ≤ 200 MB 时性能不显著劣化 | 索引覆盖查询 |

> 设计约束：所有列表查询必须命中 `(category, published_at)`、`(severity, published_at)`、`(source_key, published_at)` 等索引；聚合查询只取必要列，禁止全表 `SELECT *`。

### 5.2 安全（NFR-S）

| 编号 | 要求 | 实现要点 |
|---|---|---|
| NFR-S1 | 密码安全 | scrypt（N=16384,r=8,p=1）加盐哈希；比对用 timingSafeEqual；强度 ≥ 8 且含字母数字 |
| NFR-S2 | 会话安全 | JWT HS256，默认 12h；密钥来自环境变量或 `data/.jwt-secret`（0600）；密钥长度 ≥ 16 字节 |
| NFR-S3 | 权限 | 全局鉴权 + 路由级角色守卫；写接口仅 admin；前端隐藏不是安全边界 |
| NFR-S4 | 限流 | 登录 5 次/分/IP（仅登录路由启用限流，`global:false`）；429 返回统一信封 |
| NFR-S5 | 输入校验 | Fastify JSON Schema / 手写校验；参数类型、枚举、长度、分页上限全部校验 |
| NFR-S6 | SQL 注入 | 100% 参数化；LIKE 通配符转义；禁止拼接用户输入 |
| NFR-S7 | XSS | 前端 Markdown 渲染经 DOMPurify；报告 HTML 内联且无用户脚本；CSP/安全响应头 |
| NFR-S8 | 敏感信息 | LLM Key/Webhook 脱敏；日志 pino redact；.env 与 data/ 不入库 |
| NFR-S9 | 审计 | 所有写操作落审计（操作者/动作/对象/IP/时间），不记录明文密钥 |
| NFR-S10 | 网络安全 | 默认只监听 127.0.0.1；公网访问必须经反向代理 + TLS |
| NFR-S11 | 依赖安全 | 依赖版本锁定；不引入原生编译依赖（改用 node:sqlite） |
| NFR-S12 | 上游安全 | 不抓取需登录内容、不绕过反爬；只存标题/摘要/链接 |

### 5.3 可用性（NFR-A）

| 编号 | 要求 |
|---|---|
| NFR-A1 | 单进程启动，无外部服务依赖（不需要 Redis/MQ）；SQLite WAL + busy_timeout 5s |
| NFR-A2 | 单源、单任务失败不导致进程退出；定时任务异常被捕获 |
| NFR-A3 | 重启后数据完整（WAL checkpoint），已签发 token 在有效期内仍可用 |
| NFR-A4 | 首次启动零配置可跑（默认管理员、默认源、自动建库与迁移） |
| NFR-A5 | 健康检查供容器与运维脚本探测（DB 连通性） |
| NFR-A6 | 数据备份 = 复制 data 目录；恢复 = 覆盖 data 目录后重启（详见 06） |

### 5.4 可维护性（NFR-M）

| 编号 | 要求 |
|---|---|
| NFR-M1 | TypeScript strict，禁止 any；shared 包统一 DTO，前后端同源 |
| NFR-M2 | 新增数据源 = 写一个适配器 + 登记一行 sources，不改流水线 |
| NFR-M3 | 新增通知渠道 = 在 shared 枚举加值 + 通知模块加分支 |
| NFR-M4 | 数据库迁移版本化、只追加，启动自动执行 |
| NFR-M5 | 核心纯函数（归一化/去重/分类/报告）有 Vitest 单测；API 用 app.inject 集成测试 |
| NFR-M6 | 全中文 TSDoc + 文档 00-09；命令与路径可复制执行 |
| NFR-M7 | 日志结构化（pino JSON），字段含 sourceKey/runId/count 等上下文 |

### 5.5 兼容性与可移植性

| 编号 | 要求 |
|---|---|
| NFR-C1 | 运行环境：Windows 10/11 + Node.js ≥ 22.5（推荐 24 LTS）；Linux 与 Docker 可选支持 |
| NFR-C2 | 浏览器：Chrome/Edge 最新两个大版本（管理面板） |
| NFR-C3 | 数据库文件跨平台可迁移；路径全部通过 config/环境变量注入 |
| NFR-C4 | 时区：服务端存 UTC ISO 时间，前端按本地时区展示 |

### 5.6 合规与隐私（NFR-R）

| 编号 | 要求 |
|---|---|
| NFR-R1 | 仅聚合公开披露信息；不采集需登录/付费内容，不绕过反爬 |
| NFR-R2 | 不存储可武器化攻击代码；PoC 仅保留链接与描述 |
| NFR-R3 | 报告注明来源并链接原文，不全文转载；发布前人工复核 |
| NFR-R4 | 不采集个人信息；审计日志中的 IP 仅本机可见，保留期与库同生命周期 |
| NFR-R5 | 用户密码不可逆哈希存储；LLM Key 落库前加密/脱敏，日志脱敏 |

### 5.7 可观测性（NFR-O）

| 编号 | 要求 |
|---|---|
| NFR-O1 | 结构化日志分级（debug/info/warn/error），生产 JSON、开发彩色 |
| NFR-O2 | 每次 API 请求返回 `requestId`，与日志关联，便于排障 |
| NFR-O3 | 采集运行逐行日志落库（fetch_runs.logs），面板可查 |

| NFR-O5 | 系统信息接口暴露版本、运行时长、库大小，供外部监控抓取 |

## 6. 数据需求

### 6.1 数据实体

| 实体 | 表 | 主键 | 说明 | 关系 |
|---|---|---|---|---|
| 用户 | `users` | id | 管理员/只读用户，scrypt 密码哈希 | 1:N 审计 |
| 数据源 | `sources` | id | 采集入口与适配器配置 | 1:N 情报条目（逻辑） |
| 情报条目 | `items` | id + uid 唯一 | 去重后的事实 | N:1 源（source_key 冗余） |
| 采集运行 | `fetch_runs` | id | 一次采集的统计与日志 | 1:N 日志行（JSON 数组） |
| 报告 | `reports` | id | Markdown/HTML 正文与落盘路径 | — |
| 设置 | `settings` | key | 键值 JSON | — |
| 审计日志 | `audit_logs` | id | 写操作留痕 | N:1 用户（username 冗余） |
| 迁移记录 | `schema_migrations` | version | 迁移版本 | — |

字段级定义与索引见《03-总体架构设计》§6 与 `infra/migrations.ts`；API 字段见《09》。

### 6.2 数据量与容量估算

| 数据 | 估算 | 依据 |
|---|---|---|
| 数据源 | 20-30 行 | 内置清单 25 个左右，运营增删 |
| 情报条目 | 首年 3-8 万条 | 12 个活跃源，日均 100-300 条新增（去重后） |
| 单条条目 | 平均 2-4 KB（含 raw 快照，raw ≤ 16 KB） | title/summary/tags/raw |
| 数据库文件 | 首年 100-300 MB | 含索引 |
| 采集运行 | 每日 10-40 次 | 12 源 × 不同间隔 |
| 报告 | 每月 4-10 份 | 周报 + 专题 |
| 审计日志 | 每日 20-100 条 | 写操作量 |

> 超过 20 万条时建议按年归档或启用 retentionDays 收紧（默认 180 天）。

### 6.3 数据质量约束

| 约束 | 说明 |
|---|---|
| uid 唯一 | 数据库 UNIQUE 约束兜底去重 |
| 必填 | title 非空；fetchedAt 非空；category/severity/lang 属于枚举 |
| 时间 | ISO 8601 UTC 字符串；publishedAt 缺失时回退 fetchedAt |
| 长度 | summary ≤ 600 字（超出截断）；raw ≤ 16 KB；title 建议 ≤ 500 字 |
| 数组字段 | tags/cve_ids/ghsa_ids 存 JSON 数组字符串，读取时解析为数组 |
| 枚举一致性 | 只允许 shared 包中定义的值；新增值需迁移 + 文档同步 |
| 计数一致性 | run 的 itemsNew/itemsDuplicate 与实际入库/重复数一致 |

### 6.4 数据生命周期

```
采集 → RawItem → 归一化 → 去重 → 富化 → items（默认保留 180 天）
                                      └→ fetch_runs.logs（保留 30 天）
报告 → reports + data/reports/<id>-<type>-<date>/（长期保留，人工清理）
审计 → audit_logs（长期保留，v1.0 不提供删除）
备份 → 复制 data/ 目录（建议每周全量 + 每日增量）
```

### 6.5 敏感数据处理

| 数据 | 存储 | 传输/展示 | 备注 |
|---|---|---|---|
| 用户密码 | scrypt 哈希（含盐） | 永不返回 | 强度校验 |
| JWT 密钥 | 环境变量或 data/.jwt-secret（0600） | 不传输 | 首次自动生成 |
| LLM API Key | settings 表 | 接口脱敏（前 4 + 后 4）；日志 redact | 更新时空值=保持 |
| GitHub Token / NVD Key | 环境变量（不入库） | — | 部署文档说明 |
| 采集原始快照 raw | items.raw（≤16KB） | 详情接口不返回 | 排障用 |
| 审计 IP | audit_logs.ip | 仅 admin 可见 | 本机场景风险低 |

## 7. 边界与非目标

### 7.1 明确边界（做什么）

- 聚合**公开披露**的 AI 安全与网络安全情报，形成可检索、可统计、可成稿的知识资产；
- 自动生成报告**初稿**，最终发布由运营人工复核、点评、排版；
- 单机、单租户、内网/本机使用，默认不对公网暴露。

### 7.2 非目标（不做什么）

| 编号 | 非目标 | 原因 |
|---|---|---|
| NG-01 | 漏洞扫描、爆破、利用、武器化 | 合规红线，仅做情报聚合 |
| NG-02 | 存储/分发攻击代码 | 同上；PoC 只留链接 |
| NG-03 | 采集需登录/付费墙内容、绕过反爬 | 合规与稳定性风险 |
| NG-04 | 多租户 / 团队协作 / 细粒度数据权限 | v1.0 单机单租户，复杂度不匹配 |
| NG-05 | 移动 App / 小程序 | 管理面板为浏览器端后台 |
| NG-06 | 自动发布到公众号/星球（无人工） | 质量与合规风险，人必须复核 |
| NG-07 | 全文存储与全文检索（Elasticsearch） | SQLite LIKE 满足万级数据；不引入外部服务 |
| NG-08 | 分布式部署 / 消息队列 / Kubernetes | 单机是明确交付形态；可选 Docker 仅为打包 |
| NG-09 | 实时推送（WebSocket） | 面板刷新 + 定时任务足够 |
| NG-10 | 第三方 OAuth / SSO | 单管理员场景，账号密码足够 |

### 7.3 需求假设与依赖

1. 运行机器可访问 GitHub/NVD/CISA/MSRC/arXiv 等公开源（CNVD 需要代理，见《04》）；
2. 用户接受默认只监听 127.0.0.1；如需局域网/公网访问，按《06》配置反向代理与 TLS；
3. 运行机器 Node.js ≥ 22.5（推荐 24 LTS），具备写 `data/` 目录的权限；
4. 报告发布前有人工复核环节，本系统不承担最终发布责任。
