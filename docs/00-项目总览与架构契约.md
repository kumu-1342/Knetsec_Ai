## 1. 背景与目标

### 1.1 业务背景

运营方在做「AI × 网络安全」知识星球，每周需要产出「AI 安全情报周报」等栏目。当前人工收集存在四个痛点：

1. **分散**：GitHub Advisory、NVD、CNVD、微软 MSRC、Cisco、各厂商博客、arXiv、安全媒体……每天几十个入口；
2. **重复**：同一漏洞被 NVD、GHSA、媒体反复报道，人工去重成本高；
3. **时效**：0day/在野利用（KEV）窗口只有几小时，人工巡检必然滞后；
4. **沉淀难**：收集到的链接散落在浏览器收藏夹，无法形成可检索、可复盘、可生成报告的知识资产。

Knetsec_Ai 的目标是把「巡检 → 汇总 → 去重 → 分级 → 成稿」这条链路自动化，让人只做**判断与点评**。

### 1.2 产品目标（验收口径）

| 编号 | 目标 | 验收标准 |
|---|---|---|
| G1 | 多源实时采集 | 内置 ≥ 12 个可用数据源，覆盖 GitHub / 漏洞库 / 厂商 / 研究 / 媒体 5 类；单源失败不影响其他源 |
| G2 | 自动去重与打标 | 同一 CVE/GHSA 只保留一条；自动打 AI 安全标签、严重度、KEV 标记 |
| G3 | 自动报告 | 一键/定时生成周报（Markdown + 独立 HTML），可直接粘进星球/公众号 |
| G4 | 管理面板 | 登录、仪表盘、情报检索、来源管理、任务触发、报告中心、系统设置、审计日志 |
| G5 | 可运维 | 一条命令启动；SQLite 单文件存储；日志与运行记录可排障；部署文档齐全 |
| G6 | 工程质量 | TypeScript 严格模式、注释齐全、ESLint/Prettier、单元测试、API 文档 |

### 1.3 明确不做（合规边界）

- 不做任何**未授权扫描、爆破、漏洞利用**；只聚合**公开披露**的信息；
- 不存储/分发可直接武器化的攻击代码；对 PoC 只保留**链接与描述**；
- 不采集需登录才能访问的非公开内容，不绕过付费墙/反爬；
- 报告发布前由运营人工复核（工具只提供素材与初稿）。

## 2. 技术选型与理由

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Node.js 24 LTS** | 本机已装 v24.22；内置 `fetch`、`node:sqlite`、`process.loadEnvFile`，依赖面最小 |
| 语言 | **TypeScript 5.7（strict）** | 前后端共享类型，接口即文档 |
| 后端框架 | **Fastify 5** | 性能好、插件生态成熟、Schema 校验与 Swagger 一体化 |
| 数据库 | **SQLite（node:sqlite）** | 单文件、零运维、免原生编译；数据量（十万级）完全够用；WAL 并发读 |
| 调度 | **croner** | 轻量、支持时区与秒级 cron，无额外依赖 |
| 采集解析 | **fast-xml-parser**（RSS/Atom/arXiv）+ **cheerio**（HTML 列表页） | 覆盖 JSON / XML / HTML 三类上游 |
| 前端 | **Vue 3 + Vite 6 + TypeScript** | 组合式 API、生态成熟、构建快 |
| UI 组件 | **Element Plus 2.9** | 后台管理场景组件齐全（表格/表单/抽屉/日期范围） |
| 图表 | **ECharts 5** | 趋势图、分布图开箱即用 |
| 状态/路由 | **Pinia + Vue Router 4** | 官方推荐组合 |
| 测试 | **Vitest 3** | 与 Vite 同源，单测/集成测试快 |
| 日志 | **pino** | 结构化 JSON，生产可对接 ELK/Loki |
| 部署 | Windows 脚本 + **Docker Compose**（可选） | 本机直接跑；需要时容器化 |

> 为什么不用 Python：本机 Python 3.8.6 过旧（FastAPI/Pydantic v2 新版本已不支持），升级 Python 会污染用户环境；
> Node 24 自带 SQLite 与 fetch，可实现零原生编译、一条命令启动，更适合交付给非全栈用户长期运行。

## 4. 数据流与运行模型

```
                 ┌──────────────────────────── 管理面板 (Vue3) ────────────────────────────┐
                 │ 仪表盘 / 情报列表 / 来源管理 / 任务 / 报告 / 设置 / 审计                    │
                 └───────────────▲───────────────────────────────┬─────────────────────────┘
                                 │ REST + JWT                     │ 手动触发采集/生成报告
┌────────────────────────────────┴───────────────────────────────▼─────────────────────────┐
│                                   Fastify 服务端                                          │
│  modules/* 路由层 → service 业务层 → repo(SQL)                                            │
│  ┌─────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐                │
│  │ 调度器 cron │──▶│ 采集编排器    │──▶│ 归一化/去重   │──▶│ 富化(打标/分级)│──▶ SQLite     │
│  └─────────────┘   │ collectors/* │   └──────────────┘   └──────────────┘                │
│                    └──────┬───────┘                                                       │
│                           │ 外部 HTTP（GitHub / NVD / 厂商 / RSS / arXiv ...）             │
│  ┌────────────────────────▼─────────────────────────┐   ┌────────────────────────────┐   │
│  │ 报告生成器（Markdown → HTML，落盘 data/reports）   │──▶│ 通知（Webhook/企微/钉钉/飞书）│   │
│  └──────────────────────────────────────────────────┘   └────────────────────────────┘   │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

**一次采集的完整链路**：

1. 调度器每 5 分钟扫描 `sources` 表：`enabled=1` 且 `last_run_at + interval_minutes <= now` 的源入队；
2. 编排器创建 `fetch_runs` 记录（status=running），逐源串行/限并发执行适配器；
3. 适配器返回 `RawItem[]`（不碰数据库）；
4. 流水线：归一化（时间/分类/语言）→ 生成去重 uid → 去重（库内 + 本次批内 + 跨源标题相似度）→ 富化（CVE/GHSA 提取、CVSS、KEV、AI 安全标签、severity、importance）→ 批量入库；
5. 更新源的 last_run_at / last_status / 计数，写运行日志；
6. 若本轮新增中有 critical/KEV 条目且开启通知，推送 Webhook；
7. 周报定时任务（默认周一 08:00）聚合区间数据生成报告并落盘。

**并发与幂等**：同一时刻只允许一个采集任务运行（内存锁 + `fetch_runs.status=running` 检查）；适配器必须幂等，重复执行只产生重复条目由去重拦截。

## 5. 数据模型（SQLite）

迁移脚本：`apps/server/src/infra/migrations.ts`，启动时自动执行。

### 5.1 `sources` 数据源注册表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| key | TEXT UNIQUE | 稳定键，如 `github-ghsa`、`nvd-cve`，报告与前端引用 |
| name | TEXT | 中文展示名 |
| category | TEXT | `github\|vuln-db\|vendor\|research\|media\|community` |
| adapter | TEXT | `github_advisories\|github_search\|github_releases\|nvd_cve\|cisa_kev\|msrc_cvrf\|arxiv\|rss\|json_list\|html_list` |
| url | TEXT | 入口地址（排障用） |
| config | TEXT(JSON) | 适配器私有配置，见 §8.2 |
| enabled | INTEGER | 1 启用 / 0 停用 |
| interval_minutes | INTEGER | 采集间隔，默认 360 |
| priority | INTEGER | 越小越优先（报告排序、并发排队） |
| last_run_at / last_status / last_error | TEXT | 最近一次运行结果 |
| success_count / failure_count | INTEGER | 累计成功/失败次数 |
| created_at / updated_at | TEXT | ISO 时间 |

### 5.2 `items` 情报条目（核心事实表）

| 字段 | 说明 |
|---|---|
| uid | **去重键**：`sha256(source_key + ':' + externalId)`；无 externalId 时 `sha256(source_key + ':' + 规范化标题)` |
| source_key / source_name | 冗余来源信息，便于列表展示（源改名不影响历史） |
| title / summary / url / author | 内容字段，summary 为纯文本摘要（≤ 600 字） |
| published_at / fetched_at | 发布时间 / 抓取时间，ISO 8601 |
| category | 业务分类，见 shared `ITEM_CATEGORIES` |
| tags | JSON 数组，AI 安全标签（prompt-injection / agent / rag ...） |
| severity | critical/high/medium/low/info/unknown |
| cve_ids / ghsa_ids | JSON 数组 |
| cvss_score | REAL，可空 |
| is_kev | 1 表示已列入 CISA KEV |
| vendor | 厂商名（微软/思科/…） |
| lang | zh / en / other |
| importance | 0-100，用于排序（severity + KEV + 关键词命中 + 时效） |
| raw | 原始 JSON 快照（≤ 16KB，排障用） |
| is_read / is_starred | 运营状态 |

### 5.3 其他表

- `fetch_runs`：任务运行记录，含 `logs`（JSON 字符串数组，单行 ≤ 1000 条）；
- `reports`：报告正文 Markdown/HTML 与落盘路径；
- `users`：管理员与只读用户，`password_hash` 为 scrypt；
- `settings`：键值对，值为 JSON；键名与 shared `AppSettings` 字段一致；
- `audit_logs`：写操作审计（登录、改设置、增删源、生成报告、批量操作）；
- `schema_migrations`：迁移版本。

## 6. REST API 契约

- 统一前缀 `/api/v1`；除 `POST /auth/login`、`GET /health`、`GET /docs`、`GET /openapi.json` 外均需 `Authorization: Bearer <JWT>`；
- 成功：`{ success: true, data: T, requestId }`；失败：`{ success: false, error: { code, message, details? }, requestId }`；
- 分页：`{ items: T[], page, pageSize, total, totalPages }`；`page` 从 1 开始，`pageSize` ≤ 100；
- 写接口仅 `admin`；`viewer` 调写接口返回 403；
- 时间统一 ISO 8601（UTC），前端按本地时区展示。

## 7. 采集器契约

接口定义见 `packages/shared/src/collector.ts`：

```ts
export interface CollectorAdapter {
  readonly id: AdapterId;
  fetch(ctx: CollectorContext): Promise<CollectorResult>;
}
```

约定：

1. **只做转换**：适配器返回 `RawItem[]`，不写库、不去重、不做最终分类（可给建议值）；
2. **必填**：`title`；尽力提供 `externalId`、`url`、`publishedAt`；
3. **幂等**：同一数据重复采集必须产生相同 `externalId`；
4. **时效**：只返回最近 30 天内内容（RSS 等按配置截断），避免首次接入灌入历史数据；
5. **容错**：单条解析失败跳过并 `warnings.push(...)`，整体失败才抛错；
6. **限流**：GitHub 未认证 60 次/小时、NVD 未认证 5 次/30 秒，适配器必须控制请求量并支持 Token；
7. **注册**：在 `apps/server/src/collectors/index.ts` 的 `createCollector` 中注册，并在 `seed/sources.seed.ts` 提供默认数据源。

## 8. 去重与富化规则（流水线）

### 8.1 去重

1. 批内去重：按 uid 去重；
2. 库内去重：`INSERT ... ON CONFLICT(uid) DO NOTHING`，命中记为 duplicate；
3. 跨源标题去重（同一事件不同来源）：规范化标题（小写、去标点、去停用词）后计算 3-gram Jaccard 相似度 ≥ 0.85 且同 category 且发布时间相差 ≤ 3 天 → 视为重复，保留 priority 更高的源（priority 数值小者）；
4. CVE/GHSA 相同视为重复。

### 8.2 富化

1. **ID 提取**：正则 `CVE-\d{4}-\d{4,}`、`GHSA(-[a-z0-9]{4}){3}`；
2. **severity**：CVSS ≥ 9 → critical；≥ 7 → high；≥ 4 → medium；> 0 → low；KEV 强制 ≥ high；无分值按适配器建议；仍无 → unknown；
3. **AI 安全标签**：命中 `AI_SECURITY_TAXONOMY` 关键词 → 打 tag，并可将 category 提升为 ai-security；
4. **importance(0-100)**：severity 权重 40 + KEV 20 + 关注关键词命中 15 + 24h 内 10 + 有 CVE 10 + 有 PoC 表述 5；
5. **LLM 增强（可选，默认关闭）**：对 critical/high 条目生成 80 字中文摘要 + 影响面判断，超时 20s 失败即跳过，不阻塞流水线。

## 9. 报告生成规则

- 目录：`data/reports/<reportId>-<type>-<yyyyMMdd>/report.md` 与 `report.html`；
- 标题：`Knetsec_Ai AI 安全与网络安全周报（YYYY-MM-DD ~ YYYY-MM-DD）`；
- 章节顺序（可通过 settings.reportSections 裁剪）：
  1. 本周速览（3-5 条最重要事件 + 一句话点评占位）
  2. AI 安全（category=ai-security，按 severity/importance 排序，每条：标题 + 摘要 + 来源 + 时间 + CVE/GHSA）
  3. 漏洞与补丁（category=vuln，KEV 优先，表格化：编号 / 组件 / CVSS / 状态）
  4. 网络安全事件（category=cyber）
  5. 安全研究（category=research，含 arXiv）
  6. 工具与项目（category=tool）
  7. 政策与合规（category=policy）
  8. 本周数据统计（来源分布、严重度分布、新增数量）
  9. 下期关注（按 keywords 推荐）
- 每章最多 30 条，超出折叠为「其余 N 条见面板」；
- 正文纯 Markdown，不依赖外部图片；HTML 为单文件（内联 CSS），可直接浏览器打印为 PDF；
- 报告生成时同步写入 `reports` 表，供面板预览/下载。

## 11. 编码规范

1. **TSDoc**：所有导出函数/类/接口必须有中文 TSDoc，说明「做什么、为什么、参数/返回值、异常」；
2. **命名**：文件 kebab-case；类型 PascalCase；变量 camelCase；常量 UPPER_SNAKE；数据库字段 snake_case（SQL 内）；
3. **类型**：禁止 `any`（确需时加 eslint-disable + 注释理由）；外部数据先用 `unknown`，显式收窄；
4. **错误**：业务错误抛 `AppError`；采集器内部失败记录日志并返回 warnings，不因单源失败中断整轮；
5. **日志**：结构化字段优先 `logger.info({ sourceKey, count }, '...')`，禁止拼接敏感信息；
6. **SQL**：全部参数化；禁止 `SELECT *`（明确列名）；分页用 LIMIT/OFFSET；
7. **时间**：服务端一律 `new Date().toISOString()`；前端 dayjs 本地化展示；
8. **测试**：纯函数（归一化/去重/分类/报告）必须单测；API 用 `app.inject` 集成测试（临时内存库）；
9. **Git 提交**：`feat(scope): 描述` / `fix(scope): 描述` / `docs: 描述`，每完成一个模块提交一次；
10. **注释**：复杂 SQL、正则、业务规则必须写明「为什么」；不要给显而易见的代码加噪音注释。

## 13. 已知风险与兜底策略

| 风险 | 影响 | 策略 |
|---|---|---|
| CNVD/CNNVD 在大陆外或特定网络不可达（实测 curl 报 schannel 吊销检查失败） | 国内漏洞源缺失 | 源保留 `enabled=0`；支持 `KNETSEC_HTTP_PROXY`；文档给出代理配置；失败只记录不影响整体 |
| GitHub 未认证限流 60 次/小时 | 采集失败 | 支持 `GITHUB_TOKEN`；每源控制请求数；429 退避重试 |
| NVD 限流 5 次/30 秒 | 采集慢 | 支持 `NVD_API_KEY`；单次只拉 7 天窗口；失败自动延后 |
| RSS 源 403（如 BleepingComputer 实测 403） | 少一个媒体源 | 用 UA + 备选源，登记时标记 disabled |
| 上游结构变更导致解析失败 | 单源失效 | 适配器返回 warnings、记录 last_error，面板可见；解析失败不崩溃 |
| 数据合规（转载版权） | 法务风险 | 只存标题/摘要/链接，指向原文；报告注明来源；不全文转载 |
| 单机 SQLite 并发写 | 锁等待 | WAL + busy_timeout 5s；采集写库批量化、单事务提交 |
