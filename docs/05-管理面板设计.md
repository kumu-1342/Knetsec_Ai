# 05 · 管理面板设计（web-panel）

> 本文描述 Knetsec_Ai 管理面板的信息架构、页面与组件划分、状态管理、接口调用矩阵、关键交互与样式规范。
> 适用代码目录：`apps/web/src`；技术栈：Vue 3（`script setup`）+ TypeScript strict + Vite 6 + Element Plus 2.9 + Pinia + Vue Router 4 + ECharts 5 + axios + dayjs + marked + DOMPurify。
> 对应契约：`docs/00-项目总览与架构契约.md` §6（REST API）、§10（管理面板信息架构）、§11（编码规范）。

---

## 1. 文档定位与设计范围

管理面板是 Knetsec_Ai 的**唯一人机入口**。采集、去重、打标、报告生成都发生在服务端，面板负责三件事：

1. **观察**：仪表盘告诉运营「今天发生了什么、哪些是严重事件、哪个源出问题了」；
2. **检索**：情报中心让运营在几万条条目里按关键词、来源、分类、严重度、时间、已读/星标状态快速定位；
3. **运营**：数据源管理、手动采集、报告生成与下载、系统设置、审计日志，把「巡检 → 汇总 → 成稿」链路收拢到一个后台。

本文不重复后端实现细节（见 docs/03、docs/04、docs/09），只从**前端视角**说明「页面为什么这样组织、状态放在哪里、接口怎么调用、异常如何兜底」。

### 1.1 两类角色

| 角色 | 能力 | 前端表现 |
|---|---|---|
| `admin` | 全部读 + 全部写（增删改数据源、触发采集、批量操作、生成/删除报告、改设置、看审计） | 显示所有按钮、选择列与写操作入口 |
| `viewer` | 只读（仪表盘、情报检索、来源列表、任务历史、报告预览/下载、设置查看） | 隐藏选择列、批量操作、行内已读/星标、立即采集、保存设置、删除报告；系统设置页整体 `disabled`；审计日志路由直接拦截 |

前端角色控制只是**减少误点**，真正的权限边界在服务端：写接口要求 JWT 中 `role=admin`，`viewer` 调用返回 403，由 axios 拦截器统一提示。

### 1.2 设计原则

- **单接口取数**：仪表盘只请求 `GET /dashboard/summary`，避免多个统计接口产生口径不一致与时间点漂移；
- **服务端分页/筛选**：情报、运行记录、报告、审计全部服务端分页，前端不做二次过滤，保证「总数」与报告口径一致；
- **状态就近**：全局 Pinia 只保留登录态与少量 UI 状态，业务数据留在页面，刷新逻辑可追踪；
- **错误可恢复**：加载失败有重试入口，空数据有引导文案，长任务有进度反馈，危险操作二次确认；
- **中文优先**：Element Plus 全局 `zhCn`，字典文案全部来自 `@knetsec/shared`，与报告用词一致。

## 2. 信息架构

### 2.1 导航分组

左侧深色侧边栏（`#0b1220`）按「总览 / 情报运营 / 系统」三组组织，组标题在侧边栏折叠时隐藏：

```
Knetsec_Ai  [Logo]
├─ 总览
│   ├─ 仪表盘        /dashboard
│   └─ 情报中心      /items
├─ 情报运营
│   ├─ 数据源管理    /sources
│   ├─ 采集任务      /tasks
│   └─ 报告中心      /reports
└─ 系统
    ├─ 系统设置      /settings
    └─ 审计日志      /audit        （仅 admin）
```

侧边栏底部展示版本号、服务端运行时长、采集任务状态（运行中/空闲 + 启用源数量），让运营在任何页面都能感知「系统是否在正常采集」。

### 2.2 核心任务流

1. **首次接入**：登录 → 数据源管理确认源启用 → 采集任务「立即采集」→ 观察运行日志 → 情报中心确认数据 → 生成首份周报；
2. **日常巡检**：仪表盘看严重 7 天与 KEV → 情报中心筛「未读 + 严重度 critical/high」→ 详情抽屉判断价值 → 标记已读/星标；
3. **周报产出**：报告中心生成周报 → 预览页核对章节与数据 → 下载 Markdown/HTML → 外部发布；
4. **问题排查**：任务历史看失败源与错误 → 数据源管理「试采」验证适配器配置 → 修改 JSON 配置后重试。

## 3. 路由表

| 路径 | name | 组件 | 权限 | 面包屑分组 | 说明 |
|---|---|---|---|---|---|
| `/login` | login | `views/LoginView.vue` | 公开 | - | 账号密码登录；已登录用户访问自动跳仪表盘 |
| `/dashboard` | dashboard | `views/DashboardView.vue` | 登录 | 总览 | 指标卡 + 趋势/分布图 + 最新情报 + 最近任务 |
| `/items` | items | `views/ItemsView.vue` | 登录 | 情报运营 | 服务端分页检索、批量操作、导出、详情抽屉 |
| `/sources` | sources | `views/SourcesView.vue` | 登录 | 情报运营 | 数据源 CRUD、启停、试采；写操作仅 admin |
| `/tasks` | tasks | `views/TasksView.vue` | 登录 | 情报运营 | 调度器状态、立即采集、运行历史与日志抽屉 |
| `/reports` | reports | `views/ReportsView.vue` | 登录 | 情报运营 | 报告列表、生成对话框、下载、删除 |
| `/reports/:id` | report-detail | `views/ReportDetailView.vue` | 登录 | 情报运营 | Markdown 渲染、下载、打印 |
| `/settings` | settings | `views/SettingsView.vue` | 登录 | 系统 | 关键词/报告/通知/LLM/保留策略；保存仅 admin |
| `/audit` | audit | `views/AuditView.vue` | admin | 系统 | 审计日志分页与过滤 |
| `/:pathMatch(.*)*` | not-found | `views/NotFound.vue` | 登录 | - | 404 兜底，提供返回仪表盘/上一页 |

路由守卫（`router/index.ts`）按顺序执行：

1. 写入 `document.title`（`页面标题 · Knetsec_Ai 管理面板`）；
2. 公开路由：已登录访问 `/login` 重定向 `/dashboard`；
3. 无 token：跳 `/login?redirect=<原路径>`，登录成功回跳（仅接受站内绝对路径，防开放重定向）；
4. 有 token 但用户信息为空：调用 `GET /auth/me` 校验；失败清会话并回登录页；
5. `requiresAdmin` 路由且当前角色为 viewer：提示后跳仪表盘。

> 说明：需求评审期间发现根目录安装的 TypeScript 为 6.0.x，`baseUrl` 已被废弃（TS5101），因此 `apps/web/tsconfig.json` 删除了 `baseUrl`，`paths` 改为相对 tsconfig 的 `"./src/*"`；Vite 侧 `resolve.alias` 仍使用 `@ -> ./src`，运行行为不变。

### 4.2 页面拆解

**LoginView**：左侧品牌区（深色渐变 + 产品定位 + 三条能力说明），右侧登录卡片。表单行内错误提示 + 提交 loading；登录成功按 `mustChangePassword` 给出改密提醒，并按 `redirect` 回跳。

**DashboardView**：4 个指标卡（总情报 / 今日新增 / 未读 / 严重 7 天）+ 14 天趋势折线（全部 / AI 安全 / 漏洞三条线）+ 严重度环形图 + 分类横向柱状图 + 来源 Top10 进度条 + 最新情报列表 + 最近采集任务列表。数据全部来自 `DashboardSummary`；图表 option 由 `computed` 生成，避免手工刷新。

**ItemsView**：筛选工具栏（关键词防抖、来源/分类/严重度/已读/时间、星标/关注开关、重置）→ 批量操作条（admin、选中时出现）→ 表格（选择列、标题与来源/KEV/未读点、分类、严重度 Tag、CVSS、KEV、发布时间排序、行内已读/星标/详情）→ 分页 → 详情抽屉。导出支持 CSV/JSON/Markdown，复用当前筛选（去掉分页）。

**SourcesView**：页头统计（总数/启用/失败）、本地筛选（名称或 key、分类、启用状态）、表格（启停开关、名称/key、适配器、分类、间隔、上次运行 + 状态 + 错误摘要、成功率、操作）、新建/编辑对话框、试采结果弹窗、删除确认。

**TasksView**：调度器状态卡（调度启用/运行中标签、启用源、下次自动调度、运行中任务、定时任务列表、到期源列表）→ 当前任务进度卡（轮询时显示）→ 运行历史表格（触发、状态、耗时、来源成功数、新增/去重、错误）→ 分页 → 运行详情抽屉（统计 + 等宽日志自动滚动）。「立即采集」可选择数据源（不选 = 全部启用源）。

**ReportsView**：类型筛选 + 报告列表（标题与预览、类型、区间、条目数、生成人/时间、预览/下载 MD/HTML/删除）；生成对话框选择 daily/weekly/monthly/custom、区间、标题；生成成功后跳转预览页。

**ReportDetailView**：页头展示标题、类型、区间、条目数、生成人/时间；正文 `MarkdownViewer`；操作：返回列表、下载 MD/HTML、打印（`window.print()`，打印样式隐藏应用外壳）。

**SettingsView**：5 个设置分组卡片——关键词与打标（关注关键词、AI 安全关键词，`allow-create` 多选）、报告（回看天数、章节勾选）、通知（开关/渠道/Webhook）、LLM 增强（开关/Base URL/API Key/模型）、数据保留与采集（保留天数、默认采集间隔）。LLM Key 显示脱敏值，未修改时提交空字符串表示保持原值。

**AuditView**：按用户名/动作过滤 + 分页表格（时间、用户、动作中文标签、对象、IP、详情 JSON 弹窗）。

## 5. 状态管理

### 5.1 Pinia：`auth`

| 状态/方法 | 说明 |
|---|---|
| `token` | 初始化自 `localStorage.knetsec_token`；`setToken` 同步内存与 localStorage |
| `user` | `AuthUser`，只存内存；刷新页面后由守卫调用 `/auth/me` 重新拉取 |
| `isAdmin` / `roleLabel` / `displayName` / `avatarText` | 派生展示与权限判断 |
| `mustChangePassword` | 布局常驻横幅与登录提示依据 |
| `login(payload, silent)` | 调 `POST /auth/login`，写入 token 与用户 |
| `fetchMe()` | `GET /auth/me` 校验 token |
| `changePassword(payload)` | `POST /auth/change-password`，成功后清 `mustChangePassword` |
| `logout()` / `clearSession()` | 清 token 与用户，不负责跳转 |

### 5.2 Pinia：`app`

| 状态/方法 | 说明 |
|---|---|
| `sidebarCollapsed` | 侧边栏折叠状态（顶栏按钮切换） |
| `systemInfo` | `GET /system/info`，含版本、运行时长、库大小、计数、调度器状态 |
| `version` / `uptimeText` / `running` / `enabledSources` | 侧边栏底部展示的派生值 |

### 5.3 页面本地状态

业务数据一律放页面 `ref/reactive`，包括筛选条件、分页、列表、选中行、弹窗开关、提交 loading、轮询定时器。这样做的原因：

- 离开页面即销毁，避免全局 store 越积越多陈旧数据；
- 刷新当前页面（布局层的 `viewKey` 变更）会重新挂载组件并重新取数，语义明确；
- 定时器（关键词防抖、任务轮询）在 `onBeforeUnmount` 清理，防止后台请求泄漏。

## 6. API 调用矩阵

所有请求经 `src/api/client.ts` 的 axios 实例发出：`baseURL=/api/v1`、超时 20s、自动附加 `Authorization: Bearer <token>`、统一 `ElMessage.error` 提示、401 清 token 并跳登录（登录接口的 401 例外，交给登录页行内展示）。

| 页面 | 方法/路径 | 用途 | 权限 |
|---|---|---|---|
| 登录 | `POST /auth/login` | 登录，返回 token + 用户 | 公开 |
| 布局/守卫 | `GET /auth/me` | 校验 token、刷新用户信息 | 登录 |
| 布局 | `POST /auth/change-password` | 修改密码 | 登录 |
| 布局/侧边栏 | `GET /system/info` | 版本、运行时长、库大小、调度器状态 | 登录 |
| 仪表盘 | `GET /dashboard/summary` | 指标、分布、趋势、最新情报、最近任务 | 登录 |
| 情报中心 | `GET /items` | 分页检索（q/category/severity/sourceKey/from/to/read/starred/watched/sort/order） | 登录 |
| 情报中心 | `PATCH /items/:id` | 行内已读/星标 | admin |
| 情报中心 | `POST /items/bulk` | 批量已读/未读/星标/取消星标/删除 | admin |
| 情报中心 | `GET /items/export?format=csv\|json\|markdown` | 按当前筛选导出文件 | 登录 |
| 数据源 | `GET /sources` | 全量数据源列表 | 登录 |
| 数据源 | `POST /sources` / `PATCH /sources/:id` / `DELETE /sources/:id` | 新建/编辑/删除（key 与 adapter 创建后不可改） | admin |
| 数据源 | `PATCH /sources/:id`（`{enabled}`） | 启停（幂等，避免 toggle 翻转语义的竞态） | admin |
| 数据源 | `POST /sources/:id/test` | 试采（不写库，返回样本数与前 5 条标题） | admin |
| 采集任务 | `POST /tasks/fetch` | 触发采集，202 返回 runId | admin |
| 采集任务 | `GET /tasks/runs` / `GET /tasks/runs/:id` | 运行历史/详情（详情含 logs） | 登录 |
| 采集任务 | `GET /tasks/status` | 调度器启用、定时任务、运行中 id、到期源 | 登录 |
| 报告中心 | `GET /reports` / `GET /reports/:id` | 列表/详情（含 markdown/html） | 登录 |
| 报告中心 | `POST /reports/generate` | 生成报告（type/periodStart/periodEnd/title/itemIds） | admin |
| 报告中心 | `GET /reports/:id/download?format=md\|html` | 下载文件流 | 登录 |
| 报告中心 | `DELETE /reports/:id` | 删除报告 | admin |
| 系统设置 | `GET /settings` / `PUT /settings` | 读取（Key 脱敏）/保存 | 读登录、写 admin |
| 审计日志 | `GET /audit-logs` | 分页 + username/action 过滤 | admin |

### 6.1 文件下载兼容策略

`downloadFile()` 以 `responseType='blob'` 请求，然后按响应头分支：

- `Content-Type: application/json`：可能是统一信封（`{success,data}`）或直接返回数组（`/items/export?format=json`）。前者取 `data`，后者保留服务端原文；`success=false` 时抛出 `ApiRequestError`；
- 其他类型（`text/csv`、`text/markdown`、`text/html`）：直接用 Blob 触发下载；
- 文件名优先解析 `Content-Disposition`（兼容 `filename*=UTF-8''`），失败时使用调用方兜底名。

### 6.2 类型契约

除两个接口外，所有请求/响应类型均来自 `@knetsec/shared`（`ItemDTO`、`SourceDTO`、`RunDTO`、`ReportDTO`、`DashboardSummary`、`SettingsDTO`、`AuthUser`、`Paginated` 等），不在前端重复定义 DTO。两个例外是 shared 尚未固化的只读视图：

- `SchedulerStatus`（`GET /tasks/status` 与 `/system/info.scheduler`）：`enabled/jobs/runningRunId/dueSources`，与后端 `modules/core/context.ts` 对齐；
- `SystemInfo`（`GET /system/info`）：`appName/version/env/nodeVersion/startedAt/uptimeSeconds/dataDir/dbPath/dbSizeBytes/counts/scheduler`，与后端 `modules/system/index.ts` 对齐。

若后端后续把两者提升进 shared，前端只需删除本地定义并改为 import。

## 7. 关键交互细节

### 7.1 登录与强制改密

- 表单校验（必填）通过后才发请求；请求 `silent=true`，由页面行内 `el-alert` 展示错误原因，避免与全局 toast 重复；
- 登录失败（401）不会触发「登录已过期」提示或整页跳转；
- `mustChangePassword=true` 时：登录页 toast 提醒 + 布局顶部常驻警示条（可一键打开改密对话框）；
- 改密成功后统一退出登录，要求用新密码重新登录（避免旧 token 继续可用）；
- 密码规则与服务端一致：8-64 位且同时包含字母与数字，前端提前校验。

### 7.2 情报筛选与分页

- 关键词输入防抖 350ms，其他筛选条件变化立即查询并回到第 1 页；
- 日期范围用 `daterange`（`YYYY-MM-DD`），提交时转换为「当天 00:00:00」与「当天 23:59:59」的 ISO 时间，与服务端 `COALESCE(published_at, fetched_at)` 口径一致；
- 排序：发布时间、严重度支持表头点击（`sortable="custom"`），排序字段映射为服务端白名单 `published_at/severity`；
- 批量删除后若当前页被删空且不在第一页，自动回退一页；
- 行内标记先请求后改本地状态，失败保留原状态；详情抽屉与列表行引用同一对象，标记后两处同步。

### 7.3 导出

- 导出复用当前筛选条件（去掉 `page/pageSize`），服务端最多导出 5000 条；
- CSV/JSON/Markdown 通过下拉菜单选择；导出期间按钮 loading，服务端返回文件名后浏览器直接下载。

### 7.4 数据源配置与试采

- 新建时 adapter 可切换，切换后自动填入该适配器的配置模板；编辑时 key 与 adapter 禁用（服务端也会拒绝修改）；
- config 为自由 JSON：保存前解析并校验「必须是对象」，语法错误在输入框下方红字提示，阻止提交；
- 试采结果弹窗展示成功/失败、适配器、样本数、耗时与错误；样本最多 5 条标题，便于判断配置是否命中内容。

### 7.5 采集任务轮询

- 「立即采集」成功后拿到 `runId`，每 3 秒轮询 `GET /tasks/runs/:id`，状态非 `running` 时停止并刷新历史与调度状态；
- 进入页面时若 `/tasks/status.runningRunId` 非空，自动接续轮询（刷新页面/重进页面不会丢失进度）；
- 组件卸载清理定时器；
- 运行详情抽屉中日志逐行编号、等宽字体、追加时自动滚动到底部，便于观察长时间任务。

### 7.6 报告生成、预览与打印

- 自定义报告必须选择区间；其他类型可留空由服务端按类型推断（周报=最近 7 天）；
- 生成成功后跳转 `/reports/:id` 预览，列表同步刷新；
- 预览使用 marked 渲染 + DOMPurify 消毒，避免历史报告被注入脚本（存储型 XSS）；
- 打印调用浏览器打印，全局 `@media print` 隐藏侧边栏、顶栏与操作按钮，只输出报告正文（可直接另存 PDF）。

### 7.7 系统设置与 LLM Key

- 设置读取后填入表单；`llmApiKey` 是服务端脱敏值（如 `sk-****abcd`）；
- 保存时：输入为空或仍等于脱敏值 → 传空字符串表示「保持原值」，防止把脱敏串写入数据库；用户输入新 Key 才传真实值；
- 通知启用但 Webhook 为空、LLM 启用但 Base URL 为空、报告章节全不选时，前端提前拦截并提示。

### 7.8 空态、加载态与错误态

- 所有列表/图表都有 `v-loading`；表格空态使用 `el-empty` 并提供下一步引导（如「先触发一次采集」）；
- 仪表盘首屏失败展示 `el-result` + 重试；其他页面靠全局错误提示 + 保留旧数据，避免页面闪空；
- 系统信息、来源下拉等辅助数据失败静默，不阻塞主流程。

## 9. 工程与质量

### 9.1 类型与代码规范

- `<script setup lang="ts">` + `strict`；所有 API 返回与枚举引用 shared，不重复定义 DTO；
- 组件 props 用 `interface Props` + `withDefaults`，事件用类型化 `defineEmits`；
- TSDoc 中文注释解释「为什么」（如为什么用受控 switch、为什么轮询 3 秒、为什么下载要兼容 JSON 信封），不为显而易见的代码加噪音；
- 所有格式化统一走 `utils/format.ts`（时间 `YYYY-MM-DD HH:mm`、千分位、耗时、字节、成功率）；
- 无 `any`；外部数据（JSON 配置、下载响应）先按 `unknown` 收窄再使用。

### 9.2 构建与自检

```powershell
cd D:\Knetsec_Ai
npm run build:shared                 # 若 shared/dist 缺失
npm -w @knetsec/web run typecheck    # vue-tsc --noEmit
npm -w @knetsec/web run build        # vue-tsc + vite build → apps/web/dist
```

产物 `apps/web/dist` 由服务端 `@fastify/static` 托管；开发态 `vite` 通过 `/api` 代理到 `127.0.0.1:8787`。本地验收建议：`npm run dev` 后登录 → 采集 → 情报中心检索 → 生成报告 → 下载，逐项对照 §10 验收清单。

## 10. 已知限制与后续扩展

1. **系统信息未做独立页面**：当前只在侧边栏展示版本/运行时长/调度状态；`/system/info` 还包含库大小、数据目录、计数，可在「系统」组新增「运行信息」页做完整展示（含数据库体积趋势）。
2. **未做实时推送**：采集进度靠 3 秒轮询；后续可接 SSE/WebSocket，由服务端推送 run 状态与新增条目数，降低请求量。
3. **审计日志动作筛选为文本输入**：服务端动作枚举会随模块增加，硬编码下拉容易过期；后续可在服务端提供「动作字典」接口再改为下拉。
4. **情报详情原始字段**：shared `ItemDTO` 未暴露 `raw`，抽屉里的「原始信息」展示的是前端实际持有的字段 JSON；若排障需要完整上游快照，建议契约增加 `raw` 或在 `GET /items/:id` 返回 `rawPreview`。
5. **表格列自定义/密度切换**：目前固定列；运营数据量大时可增加「列设置（localStorage 持久化）」与紧凑密度。
6. **国际化**：当前全中文；如需英文版，可将 `utils/enums.ts` 的标签抽为 i18n key，接入 vue-i18n。
7. **图表按需引入**：当前整包引入 ECharts（Dashboard 分块约 1MB gzip 348KB）；后续可改为 `echarts/core` + 按需注册 Line/Pie/Bar 组件，进一步压缩首屏。
8. **E2E 测试**：尚未引入 Playwright；建议补充「登录 → 采集 → 检索 → 生成报告 → 下载」烟雾用例，防止接口契约漂移。
9. **移动端**：后台定位桌面（≥1366 最佳），窄屏可浏览但表格体验一般；如要移动办公，可针对情报列表做卡片式布局。
10. **主题**：设计变量已集中，后续可扩展暗色主题（Element Plus 2.9 提供 CSS 变量覆盖能力）。
